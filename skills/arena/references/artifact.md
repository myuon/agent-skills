# 人間向けのダッシュボード

アリーナを回すと、エージェントは大量に試して大量に報告する。人間が見るのは1枚だけにして、同じ場所(同じ URL、同じ artifact)を更新し続ける。新しいページを増やさない。

## 載せるもの(上から順)

0. **いま何待ちか**: 何も待っていなければ「待ちなし。ラウンド N を実行中」と書く。人間は「どうなった？」「いまどのへん？」を何度も聞きがち。それを聞かせない
1. **人間に頼みたいこと**: 何を、なぜ、返事の例。お金がかかるかどうかを先に書く。無ければ「いまは無し」と1行
2. **本物との差**: アリーナのスコアと、封印テスト・前向きの記録・本物の評価を並べる。差が開いていないかを、一番目立つ場所に出す
   - 封印テストを開けていなければ「未評価」と書く。空欄にしない
   - 2速のアリーナなら、模擬の予測と本物の結果の相関(アリーナの信頼度)の推移
3. **採用中のもの**: 版、スコア、基準線との差、補正後の有意性。取り消したものも履歴に残す
4. **試行の状況**: 通算の試行回数、検証を見た回数と上限、封印テストを開けた回数と上限
5. **打ち切りまでの残り**: 頭打ちのカウンタ、残り時間、残りラウンド
6. **ラウンドの一覧**: ラウンドごとに、何をしたかとスコア、判断(採用、棄却、保留)。新しい順で、古いものは畳む
7. **ラウンドに対するスコアの推移**と、その下に**最初の版(ラウンド0)と最良の版を、時間の軸で並べたスコアの変動**。時間帯ごとのスコアの揺れは、狙う改善幅より大きいことが多いので、「最良が上回った時間帯の数」と「差の平均」を添える
8. **最初と最後の比較**: 基準線と最良の版の比較表。成果物が目に見えるもの(ページなど)なら、最初と最後を並べて見せる
9. **わかったこと・崩れた前提**: 振り返りの要点
10. **次にやること**

## 作り方

- 中身は JSON などの1か所にまとめ、生成スクリプトで HTML にする。ラウンドの終わりに、毎回再生成して差し替える
- スマホで読める幅で作る。外部の CDN を使わない自己完結の HTML にしておくと、どこでも開ける
- 専門用語は、初めて出たところで1行の説明を付ける
- スコアの推移のグラフには、基準線と、封印テストや前向きの結果の点を同じ軸に重ねる。スコアだけが伸びて本物が横ばいなら、それが一目で分かるようにする
- アリーナ用のダッシュボードは、調査や発見の報告用のものとは別にする。混ぜると、進み具合が埋もれる
- 開始時の版(ラウンド0)を必ず保存しておく。後から基準として比べられなくなる
- ダッシュボードに行ごとの予測などの細かいデータは載せない。集計だけにする。細かいデータを見ると、検証への作り込みが進む
