# 本物の評価が遅いときの模擬評価器

SEO、集客、新製品の反応のように、本物の結果が返るまで数週間かかる題材では、施策を打つたびに待っていると改善が止まる。速い模擬評価器(数分で1周)と、遅い本物の評価(1〜3週間で1周)を交互に回す。

```
速いアリーナ(模擬評価器)で候補を作る ─▶ 本物で評価する ─▶ 予測と実際の相関を記録
        ▲                                                      │
        └────── 本物の結果で模擬評価器を学習し直す ◀───────────┘
```

## 模擬評価器の作り方

3層を組み合わせる。SEO を例にする。

### 1. 代理モデル(学習させる)

- 狙う対象ごとに、実際の上位の結果を集める。SEO なら、検索語ごとの上位20件の検索結果とそのページ
  - 取得は規約に沿った方法で行う。SEO なら SERP API を使い、検索エンジンを直接スクレイピングしない。ページの取得は robots.txt を守り、間隔を空ける
- 特徴は、自分で動かせるもの(ページの中身)と、動かせないもの(ドメインの強さ、被リンク)の両方を入れる
  - 動かせないものを入れないと、「中身を磨けば勝てる」と勘違いしたモデルになる
  - SHAP などで、スコアを「動かせる寄与」と「動かせない寄与」に分け、エージェントには動かせる寄与だけを最適化させる。同時に「この条件なら何位が限界か」も出せるので、狙う対象の選び方に使える
- 学習は順位のランキング学習(LightGBM の lambdarank など)
- 一部の対象を封印する。例: 秘密の塩と対象名のハッシュで2〜3割を選び、学習にも候補づくりにも使わない。採点器の CLI も、封印した対象の採点を拒否する
- 封印した対象での順位相関を、模擬評価器の精度として記録する

### 2. LLM の審査団

- 自分の候補と上位の実物を、名前を伏せ、順番を入れ替えて並べる。基準は1つ(例: 検索した人の目的を満たすか)
- 審査員は、別のモデルや別のプロンプトで複数にする。一致度(Kendall の W など)が低い件は点に使わない
- 較正: 自分の候補を入れず、実物の2位・6位・15位などを伏せて並べ、実際の順位どおりの点になるかを確かめる
- 近い版どうしの差は、絶対点では出ない。前の版と新しい版を並べた対比較にする。採用の条件は、過半数でなく大多数(5人中4人など)にする。空の検定で、過半数では偶然に通ることを確かめておく
- 審査員が指示に反して全部に同じ点を付けることがある。出力の分散を検査する

### 3. ごまかし防止の門(合否のみ)

1つでも落ちたら0点にする。SEO なら次のとおり。
- 登録と読み取りができる(canonical、noindex、重複した title や H1)
- 表示速度、ページの重さ
- 構造化データが正しく、本文と一致している
- 薄い内容でない(最低の文字数、ツール・表・手順のどれかがある)
- 既存ページと重複していない(文字 5-gram の Jaccard < 0.5 など)
- 検索語を詰め込んでいない

採点器のコードはハッシュで凍結し、エージェントは触れない。

## 本物とのつなぎ方

- **判定は本物でだけ行う**。模擬評価器の点は、ふるい分けにしか使わない
- **速報の指標で待ち時間を縮める**。SEO なら、遅い順に次のとおり
  1. クローラーの巡回(サーバーログ)
  2. 登録状況(URL 検査 API)
  3. 別の検索エンジンの受付(IndexNow)
  4. 公開3〜7日の表示回数
  5. 本物の順位(7〜21日)。表示されない対象は圏外として扱う(例: 順位100)
- **信頼度を毎周記録する**。予測と実際の順位相関(圏外を含む版と除く版)、登録率、初期の表示
- **信頼度で次の動きを決める**。累積のサンプルが一定数を超えたら、たとえば次のように分ける
  - 相関 ≥ 0.4 で、既存より良い: 広げる
  - 0.15〜0.4: 1周に1つだけ直して続ける
  - 一定数を超えても < 0.15 で、既存を上回らない: 作り込みをやめる(観測は続ける)
- **学習し直す**。本物の結果を、重みを付けて代理モデルの学習データに戻す。自分の対象での本物の結果が、一番価値のあるデータになる
- **特徴ごとの信頼度**: 特徴を変えた方向と順位が動いた方向が合う割合を測る。低い特徴(例 < 0.6)は最適化させず、値を上位の中央値に固定する

## 既存の資産と混ぜない

本物の評価で、既に公開しているものを使うときは、データが混ざらないようにする。

- **既存のものは観測だけにする**。実績を代理モデルの学習データとして読むだけで、書き換えない
- **実験の置き場を分ける**。例: 同じドメインの専用サブディレクトリに置き、計測は URL の接頭辞で分ける
- **持ち物の台帳**: 対象ごとに持ち主(既存、アリーナ、別の実験)を1つだけ持たせる。書き込みの関数で、持ち主でない対象、凍結中の対象、置き場の外への書き込みを拒否する
- **判定日までの凍結**: 別の実験の判定を待っているものは、判定日まで誰も触らない
- **変更の記録**: すべての変更を、日時つきで1行ずつ残す
- **公開前の門**: 門と審査団を通るまで公開しない(SEO なら noindex)。サイト全体の評価を下げないため
- **共食いを避ける**: 既存のものと同じ対象(同じ検索語)を狙わない

## 気をつけること

- 模擬のスコアが大きく伸びても、審査団の点は動かないことがある。語順や構造化データの有無など、模擬評価器の癖を突いているだけのことが多い
- 模擬評価器の天井(例: 本文の長さの上限)が、改善の条件とぶつかることがある。ぶつかる条件は門から外し、記録だけにする
- 模擬評価器の精度の向上が、モデルの改善でなく測定の安定化(標準誤差の縮小)だけのことがある
- 本物の答え合わせの前の結論は、すべて暫定として扱う
