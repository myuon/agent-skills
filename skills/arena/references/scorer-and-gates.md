# 採点器と採用の門

## スコアを本物に近づける

アリーナのスコアが本物(お金、順位)からずれていると、エージェントはずれた方向に最適化する。

- 予測精度(相関、AUC)だけで採用しない。予測を使って行動したときの損益まで計算する。予測の相関を上げても損益が変わらない例は珍しくない
- 損益の近似が粗いなら、近似の妥当性を別のシミュレータで確かめる(10分ごとの合計の相関、約定の一致率など)。近似が見ないもの(在庫の上限、手仕舞い)は明記する
- 「行動しない」ことで門を通る抜け穴を塞ぐ。例: 約定数が基準線の半分以上、という条件を足す
- コスト、税、不利な約定を、スコアかストレス条件に入れる。回転の多い戦略は、税と約定コストで買い持ちに負けやすい
- 候補に目的を教える。お金の門で採否を決めるなら、train のお金のラベルを候補の学習にも渡す。渡さないと、候補は門が数えるものを学べない

## 主スコアと門の分け方

- ループが追う主スコアは、お金の単位の1つの数字にする。補助の指標は門にして、主スコアとトレードオフさせない
- **主スコアに最悪値や下位の値を使わない**。リスクを取らない候補が勝ち、勝てなくなる。疑似世界や窓をまたぐなら中央値を使い、最悪の世界・窓は「基準線を下回らない」という床の門にする
- リスクは、最大下落の上限のような硬い制約で管理する。上限の内側では、リスクを取った分の伸びをそのまま点にする
- **基準線は2本以上**。何もしない基準線(買い持ちなど)に加えて、強くて単純な基準線(等ウェイトなど)を必ず門に入れる。工夫を積んだ候補が、単純な基準線に検証で負けることは多い

## 比較のしかた

- **対応ありで比べる**。同じ seed、同じ fold、同じ期間で、新旧の差を取る。差の標準誤差を出す
- **交互に回す**。実行時間や負荷に結果が左右されるなら、seed ごとに新旧を順番を入れ替えて交互に実行する。時間制限の探索は、反復数を固定した比較もする
- **時系列はブロックブートストラップ**で差のばらつきを出す。ブロックの長さは系列相関より長くする
- **ノイズ幅を知っておく**。20 seed の平均の誤差幅、検証期間の長さに対する Sharpe の誤差幅などを、契約に書いておく
- **差が標準誤差の2倍未満なら「効かなかった」と記録する**
- **使っていない seed や期間で確かめる**。最良を選んだだけの当たりは、新しい seed で消える
- **fold が欠けたら不合格にする**。計算できない fold(予測が定数になったなど)を平均から飛ばすと、スコアが上振れする。台帳には欠損として残す

## 多重検定

試行を重ねるほど、最良の結果はまぐれに近づく。

- 全試行を自動で記録する。下見、近傍の確認、ストレスの確認も1回と数える。記録しない評価は禁止する
- **Bonferroni**: 片側の p に、同じ split で試した評価の数 N を掛ける
- **Deflated Sharpe Ratio (DSR)**: N 回の雑音から期待される最大の Sharpe を差し引いて評価する。N は (戦略, パラメータ) の異なる組の数
  - 試行どうしが強く相関していると分散が小さく出て、DSR は楽観的になる。記録外の試行も N に入らない。DSR は「楽観側の上限」として読む
- **PBO (CSCV)**: 検証が短いと推定が雑音だらけになる。合否には使わず、報告にとどめてよい
- 比較の相手が「直前の採用版」だと、累積の改善に対する補正が緩くなる。ときどき最初の基準線との差も補正つきで見る

## 門の例

門は採点器のコードに入れ、通らなければ採用も記録もできないようにする。

| 門 | 内容 |
| --- | --- |
| 基準線 | 何もしない基準線と、素朴な基準線の両方に勝つ |
| 部分期間 | 設計用の前半・後半それぞれで、基準線比 −2% より悪くない |
| 制約 | 最大下落 20% 以下など |
| 効果の大きさ | 差が +δ 以上(事前に決めた最小の意味のある改善) |
| 有意性 | 補正後の p < 0.05、または DSR ≥ 0.9 |
| fold | 過半数の fold で勝ち、最新の fold でも勝つ |
| 劣化なし | 主要な副指標が一定以上下がらない |
| 近傍 | 数値パラメータを1つずつ ±20% 動かし、基準線に勝つ近傍が 80% 以上、指標の中央値が中心の 70% 以上。結果が変わらない近傍は効いていないパラメータとして除く |
| ストレス | コスト増、不利な約定(例 約定価格を 0.25×|終値−始値| だけ悪くする)、税引き後でも基準線に勝つ |
| お金 | 本物の物差しに近い指標でも、差が正かつ z ≥ 1 など |

- 学習が極端に小さい fold(ウォームアップの fold)は、門から外して表示だけにする。小さい fold が門を支配することがある
- 門の閾値を変えるときは、版を上げて全採用を再評価する

## データが少ないときの頑健性の確認

新しいデータを待たずに、今のデータで確かめる。どれも候補の採用前に走らせ、各評価を試行回数に数える。
- **ブロックブートストラップ**: 評価区間を時間のブロック(例: 30分)に分けて再標本化し、差の z を出す
- **組み合わせの交差検証(CPCV)**: 「勝つ組み合わせの割合」を門にする([augmentation.md](augmentation.md))
- **悲観のストレス**: 待ち行列を2倍にする、判断の遅延を2倍にする、評価の時刻を遅らせる、リベートを無くす、約定価格を不利にする、税を引く。各条件で基準線に勝つ
- **パラメータの近傍**: 宣言した数値パラメータを1つずつ ±20% 動かす。整数のパラメータは整数に丸める(小数になって落ちる事故があった)。戦略のインターフェースが近傍の上書きを受け付けるかをテストで縛る
- **グループを抜く検定**: 対象(銘柄、ペア、検索語の群)を1つ抜いて学習し、抜いたもので評価する
- **疑似世界と時間の窓**: [augmentation.md](augmentation.md)
- **利益の集中度の分解**: 利益のうち上位3・10の対象、特定のテーマ、特定の月が占める割合を出す。上位の数対象を外すと基準線を下回るなら、偶然の当たりに近い。これは必要条件で、十分条件ではない

## 空の検定

門が誤って「改善」と言わないかを確かめる。

- 同じ候補どうしを比べ、門を通らないことを確かめる
- 基準線そのものを候補として出し、採用されないことを確かめる
- LLM の審査団を使うなら、同じページどうしを比べさせ、「新しいほうが良い」と言わないことを確かめる。過半数の賛成では偶然に通ることがある
